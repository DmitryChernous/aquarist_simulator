# Симулятор аквариумиста

План разработки игры. Документ организует работу по этапам и фиксирует журнал версий.

## Концепция

Экономический симулятор с элементами эко-симуляции. Игрок — владелец магазина аквариумистики: выставочный зал, разводня рыб и сервисные услуги.

Четыре игровых режима образуют **один общий геймплейный цикл**:

```
Закупка рыб → Обустройство аквариумов (условия) → Выставочный зал (покупатели)
                        ↑                                          ↓
                   Разводня (своё производство)              Доход → деньги
                        ↑                                          ↓
                  Сервис (обслуживание чужих аквариумов)   ←  Репутация/навык
```

### Режимы

1. **Выставочный зал** — покупатели приходят и выбирают рыбу. Нужно обустраивать помещение и повышать привлекательность.
2. **Обустройство аквариумов** — подбор рыб для аквариума по условиям (температура, жёсткость воды, растительность, объём), декор и оборудование, влияющие на привлекательность зала.
3. **Закупка / разводня** — экономика магазина: когда и какую рыбу купить для перепродажи, когда вложиться в собственную разводню, оптовые продажи.
4. **Сервис** — заработок на обустройстве и обслуживании аквариумов клиентов.

### Ключевая механика: совместимость

У каждого вида рыб есть требования (температура, жёсткость, растительность, минимальный объём). Несовпадение → стресс, болезни, снижение привлекательности и продаж. Логика совместимости прошита во все режимы.

## Технологии

- **Vite + TypeScript** — сборка, строгая типизация для растущей симуляции.
- **Canvas** — отрисовка сцены (аквариумы, рыбы-фигуры).
- **DOM** — интерфейс (панели, магазин, статистика).
- **localStorage** — сохранение прогресса.
- **GitHub Pages** — автодеплой при каждом push в `main`.

## Архитектура

```
src/
  data/        fish.ts      — каталог видов рыб (цена, требования по воде, объём)
               aquarium.ts  — модели аквариумов (габариты, объём)
               decor.ts     — декорации: растения, камни, коряги (поштучно)
               water.ts     — реестр параметров воды (15 параметров, кейжуал/хардкор)
               shop.ts      — оборудование (с настраиваемыми параметрами), стеллажи
  sim/         aquarium.ts  — аквариумы/склады, расчёт воды, рекалькуляция O₂/свет
               conditions.ts — совместимость условий воды и вида
               health.ts     — здоровье рыб, стресс, эффекты оборудования
               economy.ts    — деньги, покупка/продажа, ежедневное содержание
               buyers.ts     — покупатели, привлекательность зала/витрины
  ui/          render.ts    — отрисовка аквариума (canvas)
               panels.ts    — интерфейс: зал, аквариум, склад, магазин (DOM)
  main.ts      — игровой цикл, состояние, действия
  save.ts      — сохранение в localStorage (миграция v3 → v4)
  timing.ts    — игровое время, длительность дня
```

Симуляция отделена от рендера: игровая логика чистая (без DOM), тикает по игровому времени.

## Запланированные улучшения

Список заявленных доработок. Каждый пункт реализуется отдельной задачей: сначала изучается вопрос, рассматриваются варианты/лучшие практики, уточняются требования и только потом код. Дизайн-решения, помеченные «на этапе реализации», не закреплены заранее.

1. **Фикс сдвига контента от `purchases-block` (баг).** Сейчас блок «В пути от поставщика» вставляется в начало сетки рыб (`storeGrid.prepend`) и занимает всю строку → после каждой покупки (ре-рендер) карточки рыб и кнопки уезжают вниз. Задача: вывести это из потока сетки в не сдвигающую область (sticky-шапка магазина / плавающий индикатор), сохранив пер-карточную подпись «В пути: N · День …». Общий принцип: действия игрока (покупка, перемещение), не направленные прямо на передвижение элементов, не должны сдвигать уже отображённые элементы. Файлы: `src/ui/panels.ts` (renderStoreFish ~1671), `src/style.css` (.purchases-block).

2. **Покупка рыбы у поставщика по количеству.** Сейчас одна кнопка = всегда заказ 1 рыбы (`onOrderFromSupplier`, qty=1, `src/main.ts` ~577). Задача: дать игроку выбирать желаемое количество и показывать итоговую сумму. Способ ввода (степпер ± на карточке / накопление / модальное окно) — на этапе реализации. Файлы: `src/ui/panels.ts`, `src/main.ts`.

3. **Переделка блока информации аквариума (room-aside `aq-info`).** Сейчас всё одним списком строк (~`src/ui/panels.ts` 860–920) — трудно читаемо. Задача: разбить на наглядные группы/индикаторы, не отображать всё разом, предусмотреть просмотр подробностей (группы со сворачиванием / вкладки / т.п.). Способ — на этапе реализации. Файлы: `src/ui/panels.ts`, `src/style.css`.

4. **Индикатор вместимости аквариума.** Сейчас в info только число рыб, без занятого/оставшегося места. Задача: прогресс-бар занятых литров (или доступных рыб) + «осталось N рыб» с учётом `usedVolume`/`canStock`/`SALE_VOLUME_FACTOR`. Где и как — на этапе реализации. Файлы: `src/ui/panels.ts`, `src/style.css`.

5. **Переработка механики заказа у поставщика (отдельная большая задача).** Сейчас покупка блокируется, если прямо сейчас нет свободного места в аквариумах (`freeStockSpace < 1`, `src/main.ts` ~584), и проверка по каждой рыбе отдельно. Проблемы: (а) нельзя заказать без аквариума сейчас, хотя рыба приезжает на следующий день и место можно обустроить; (б) нельзя купить много мелких рыб, которые по отдельности помещаются, но вместе не влезают. Задача: переработать правило допуска к заказу (количество, срок прибытия, агрегированная проверка, предупреждения). Файлы: `src/main.ts`, `src/sim/economy.ts` (+ возможно данные вместимости).

6. **Больше начального оборудования на складе.** На старте `rackInventory: ['heater','thermometer','airPump','filter']` (4 из 8 слотов, `src/save.ts` ~69), нет `light` и `co2`. Задача: добавить больше исходного оборудования на тестовый период. Файл: `src/save.ts`.

## Идеи на будущее

- **Свободная расстановка предметов в аквариуме** (замена удалённой механики «Дизайн»): игрок размещает декор (растения, камни, коряги) по координатам внутри аквариума, а не по каталогу «+декор». Позиции влияют на внешний вид и привлекательность, при желании — на условия (растительность/укрытия). Требует системы координат в AquariumState (задеклации d.x/d.y уже есть в drawDecor).
